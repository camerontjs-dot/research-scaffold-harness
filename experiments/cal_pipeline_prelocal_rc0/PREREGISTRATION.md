# CAL Pipeline pre-local pressure campaign RC0

## Classification

Draft Research Infrastructure + bounded integration pressure campaign. No production component is modified. No merge, release, promotion, Contract E production authorization, execution, or MainFrame mutation is authorized by this experiment.

## Question

Can the exact currently frozen CAL Pipeline component candidates interoperate under one pinned cross-repository manifest, preserve identities across every handoff, fail closed under hostile seam mutations, and localize failures to the correct stage strongly enough to justify moving the same objects into local end-to-end smoke testing?

This is not a quality estimate for retrieval or CAL semantics.

## Frozen subjects

The exact subject identities are in `MANIFEST.json`. The campaign must fail rather than silently substitute newer heads.

## Primary positive canary

One synthetic strict-comparison claim is intentionally simple and inside CAL's maintained semantic envelope:

`Women had a higher rate than Men.`

The supplied evidence world contains the exact statement. The canary is expected to traverse:

`ClaimGate -> Contract A 2.0 -> Evidence Bundler 10/3 -> Contract B 1.2 -> typed CAL target adapter -> current CAL integration candidate -> Contract C2 materialization -> Decision C2 ingress -> Contract D 1.0 -> Contract E research dry-authorization fixture`

Current pipeline gaps must remain explicit. In particular:

- Claim Profile / Evidence World Profile are shadow-only and do not steer the run;
- retained-candidate admission is a test-harness decision, not hidden EB semantics;
- CAL typed-target construction is an explicit test adapter until the upstream typing/gate architecture is qualified;
- Contract E is research-only and may produce only a dry authorization receipt over a synthetic disposable target. No real effect is executed.

## Hard gates

1. Every checked-out repository HEAD equals its pinned SHA.
2. ClaimGate produces a valid authoritative Contract A object for the canary and does not alter the root proposition.
3. Released Contract A validation accepts the exact object and rejects stale-root / stale-handoff mutations.
4. EB consumes the exact Contract A object, preserves proposition identity/text/hash, uses exact 10/3 profile, and emits deterministic native + Contract B artifacts.
5. EB rejects tampered Contract A instead of repairing or normalizing it.
6. CAL canonical Contract B intake accepts the exact B1.2 bundle and exact typed target, rejects stale text hash and aliased proposition ID, and deterministically emits a native result.
7. The positive canary concludes `supported` under `strict_comparison`.
8. A Contract C2 object materialized from the actual current CAL `AuditContext` + native result validates structurally against exact C2 authority and remains deterministically canonical.
9. The campaign explicitly tests whether C2's frozen producer/policy authority can resolve the current CAL semantic implementation `847cc970...`; a failure here is preserved as a real seam blocker, not patched in place.
10. Decision C2 ingress consumes only the exact C2 object + exact B binding and emits canonical Contract D 1.0. Stale C2 hash, wrong B binding, target substitution, and C1/C2 confusion must fail closed.
11. Contract E research evaluation remains non-conferring: Decision/Contract D support does not itself create operational authority. Revoked/expired/wrong-target/ambiguous-target cases must deny.
12. Exact replay into fresh directories is byte-identical or canonically identical wherever the component promises determinism.
13. Failure-localization controls stop at the intended stage and do not get laundered into a downstream success state.

## Pressure surface

The campaign should attempt at least these mutation families:

- identity: stale SHA/hash, alias ID, wrong upstream object, cross-proposition replay;
- structure: removed child/member, duplicate target/reference, unknown field/version/profile;
- authority: fabricated self-consistent object, wrong selected authority root, stale producer identity;
- evidence: wrong passage/source binding, retained-vs-admitted leakage, unavailable/unsupported evidence;
- semantic state: unsupported family, mixed relations, unresolved/non-deciding relation, negative direct-event polarity where available;
- decision: wrong B binding, wrong target hash, missing proposition/contribution, C1/C2 substitution;
- authorization: revoked/expired state, wrong subject/domain/operation/scope/target, receipt replay assumptions, ambiguous target reference;
- transport/apparatus: non-empty output directories, deterministic replay, exact checkout drift.

## Disposition

Use one of:

- `SUPPORTED_FOR_LOCAL_PIPELINE_SMOKE_WITH_BOUNDS`
- `INCONCLUSIVE_PRELOCAL_PRESSURE`
- `BLOCKED_AT_<SEAM>`
- `FALSIFIED_PRELOCAL_INTEROPERABILITY_CLAIM`
- `APPARATUS_FAILURE_BEFORE_SCIENTIFIC_COMPARISON`

A green workflow is necessary but not sufficient for the strongest disposition. Any expected-failure control that unexpectedly passes is a scientific failure and must make the campaign non-green.
